OBS Safe VST3 Host v0.6.1 — Windows x64
=========================================

What this installs
------------------
OBS Safe VST3 Host adds two normal OBS audio filters:

  VST 3.x Plug-in   — simple one-effect Safe Host
  VST3 Rack         — isolated serial multi-effect Rack

Third-party VST3 DSP and vendor GUI code run in helper processes instead of
inside obs64.exe. Plug-in scanning is isolated as well.

Recommended install — Smart Setup.exe
-------------------------------------
1. Close OBS Studio completely.
2. Download the latest stable release only from:
     https://github.com/masarray/obs-vst3/releases/latest
3. Run:
     OBS-Safe-VST3-Host-v0.6.1-Setup-x64.exe
4. Select the OBS root folder that contains:
     bin\64bit\obs64.exe
5. Click Install.
6. Start OBS Studio.

Single effect quick start
-------------------------
1. Open an audio source -> Filters -> + -> VST 3.x Plug-in.
2. Keep "Installed plug-ins" for normally installed VST3 effects, or browse to
   a .vst3 bundle in a non-standard location.
3. Select the effect.
4. Click "Open Plug-in Interface" to open the native vendor GUI.

Multiple effects — VST3 Rack
----------------------------
1. Open an audio source -> Filters -> + -> VST3 Rack.
2. Click "Open Rack" in Rack Properties.
3. Add compatible VST3 effects in the graphical Rack Editor.
4. Reorder, bypass, replace or remove slots as needed.
5. Open a plug-in's native vendor editor when you need its detailed controls.
6. Close OBS normally. The latest working Rack is saved automatically.
7. Reopen OBS. The Rack restores its latest working chain without requiring a
   named preset.
8. Use named Rack presets when you want reusable named chains or deliberate
   recall points independent of the current working session.

The Rack is a serial effects lane in v0.6.1. Free-form graph routing, sidechain,
MIDI/instruments and arbitrary multichannel processing are not part of this
release.

Durable Rack recall in v0.6.1
-----------------------------
Each OBS VST3 Rack filter owns a durable working-session file derived from its
OBS source UUID under the module configuration directory.

The working session stores Rack topology, bypass state and VST3 component/
controller state. Writes are CRC-protected and atomic, with last-known-good
recovery. OBS scene-collection save/close requests a bounded fresh state capture
from the isolated helper.

State capture is coordinated at a DSP-safe frontier. The realtime path never
waits on a control mutex: when a valid wet result cannot be produced safely, the
Rack remains fail-dry/pass-through.

Slow saved chains restore dry-first and publish the complete restored chain only
when materialization is coherent. This avoids coupling OBS/Rack availability to
the aggregate startup time of third-party plug-ins.

If durable Rack storage cannot be established, the filter does not silently run
as a writable nonpersistent Rack. It stays dry and reports Needs Attention so a
storage problem cannot masquerade as a successful persistent session.

Installed VST3 effects are discovered automatically. Install only VST3 plug-ins
from vendors you trust.

What files are installed
------------------------
The installer installs only these product files into the selected OBS root:

  obs-plugins\64bit\obs-safe-vst3.dll
  obs-plugins\64bit\obs-safe-vst3-host.exe
  obs-plugins\64bit\obs-safe-vst3-rack-host.exe
  obs-plugins\64bit\obs-safe-vst3-scanner.exe
  data\obs-plugins\obs-safe-vst3\locale\en-US.ini

The installer does not install, replace or modify OBS itself. It remembers the
validated OBS root for future updates and registers a normal Windows uninstaller.

Portable / manual install
-------------------------
Advanced users can use:

  OBS-Safe-VST3-Host-v0.6.1-Windows-x64-Portable.zip

Extract it directly into the OBS root. The package includes:

  obs-plugins/64bit/obs-safe-vst3.dll
  obs-plugins/64bit/obs-safe-vst3-host.exe
  obs-plugins/64bit/obs-safe-vst3-rack-host.exe
  obs-plugins/64bit/obs-safe-vst3-scanner.exe
  data/obs-plugins/obs-safe-vst3/locale/en-US.ini
  README-FIRST.txt
  UNINSTALL-MANUAL.cmd

Uninstall
---------
Smart Installer users can uninstall from Windows Installed Apps.

For a manual/ZIP installation, close OBS and run UNINSTALL-MANUAL.cmd from the
OBS root, or remove only the project-owned files listed above.

Windows SmartScreen / Unknown publisher
---------------------------------------
The current Windows package is not commercially Authenticode-signed. Windows
may therefore show "Unknown publisher" or a SmartScreen reputation warning.

Do not disable Defender or SmartScreen globally. Download only from the official
GitHub Releases page and verify SHA256SUMS.txt when you want an additional file
integrity check.

Example:

  Get-FileHash .\OBS-Safe-VST3-Host-v0.6.1-Setup-x64.exe -Algorithm SHA256

Current compatibility scope
---------------------------
Supported today:
- Windows x64.
- OBS Studio 29.1+ compatibility floor.
- VST3 audio effects.
- Mono/stereo Float32 processing.
- Single VST3 Host.
- Serial multi-effect VST3 Rack.
- Graphical helper-owned Rack Editor.
- Add / replace / remove / reorder / bypass Rack workflow.
- Automatic working-Rack recall across normal OBS restarts.
- Named Rack presets for reusable chains.
- Installed VST3 discovery.
- Native vendor VST3 editor when provided by the plug-in.
- Single Host state persistence and recovery.
- Crash-isolated helper runtime and scanner.
- Dry fail-open/pass-through audio and bounded recovery behavior.

Not in the complete current scope:
- VST3 instruments / MIDI.
- Full sidechain / multiple-audio-bus routing.
- Free-form graph routing.
- Arbitrary multichannel layouts.
- Float64-only fallback.
- macOS or Linux runtime packages.

A specific third-party plug-in can still expose vendor-specific behavior, so no
responsible host should claim guaranteed compatibility with every VST3 ever made.

Crash-isolation boundary
------------------------
Single Host VST3 DSP/vendor UI code runs in obs-safe-vst3-host.exe. Rack VST3
DSP, Rack UI and vendor UI ownership live in obs-safe-vst3-rack-host.exe. VST3
candidate probing also runs outside OBS.

If a valid isolated wet result is unavailable, the product is designed to keep
original dry/pass-through audio instead of deliberately stalling the realtime
OBS audio path.

This materially reduces the failure surface compared with direct in-process
plug-in hosting, but it is not a guarantee that Windows, OBS, drivers, hardware
or malicious native code can never fail.

Security note
-------------
Crash isolation is not a malware sandbox. A VST3 is native code and still runs
with your Windows user permissions inside the helper process. Only load plug-ins
from vendors you trust.
