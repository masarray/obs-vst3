OBS Safe VST3 Host — Windows x64 Stable
========================================

Recommended for most users: Smart Setup.exe
---------------------------------------------
1. Close OBS Studio.
2. Run the newest:
     OBS-Safe-VST3-Host-v<VERSION>-Setup-x64.exe
3. For a normal OBS installation, keep Standard OBS Studio (recommended).
   Setup installs the plug-in into OBS's ProgramData plug-in layout.
4. For OBS Portable or a custom self-contained OBS folder, choose
   Custom / Portable OBS folder and select the OBS root containing:
     bin\64bit\obs64.exe
5. Click Install.
6. Start OBS Studio, open an audio source -> Filters -> + ->
   VST 3.x Plug-in (Safe Host).
7. Click Rescan Installed Plug-ins and choose an effect.

The runtime package contains:
  obs-safe-vst3.dll
  obs-safe-vst3-host.exe
  obs-safe-vst3-scanner.exe
  locale\en-US.ini

The Smart Installer does not install or modify OBS itself. If OBS is open,
Setup asks you to close it before copying files.

Portable ZIP / advanced install
-------------------------------
The portable ZIP is designed to be extracted directly into the OBS root:

  obs-plugins/64bit/obs-safe-vst3.dll
  obs-plugins/64bit/obs-safe-vst3-host.exe
  obs-plugins/64bit/obs-safe-vst3-scanner.exe
  data/obs-plugins/obs-safe-vst3/locale/en-US.ini
  README-FIRST.txt
  UNINSTALL-MANUAL.cmd

Uninstall
---------
The Smart Installer registers OBS Safe VST3 Host in Windows Installed Apps.

For a portable installation, close OBS and run UNINSTALL-MANUAL.cmd from the
OBS root, or remove only the project-owned files listed above.

Scanner behavior
----------------
The stable Windows runtime scans standard Windows VST3 locations. Each
discovered .vst3 bundle is probed in its own short-lived scanner child process.
A hung probe is terminated after its timeout and skipped. The resulting cache
is stored under the current user's LocalAppData folder and read by the OBS
properties UI.

Use Browse / Custom VST3... for a non-standard location.

Phase S stable behavior
-----------------------
- Third-party VST3 DSP runs in obs-safe-vst3-host.exe, not obs64.exe.
- Scanning also occurs outside OBS, with a separate child probe per bundle.
- Native vendor VST3 GUI is hosted by the isolated helper when available.
- Generic normalized parameter controls are available as fallback.
- Full VST3 component + controller state is persisted with CRC validation.
- A last-known-good state checkpoint is used when recreating the helper.
- DSP work runs on a dedicated MMCSS Pro Audio worker, separate from UI/control.
- Protocol v6 publishes separate control and DSP heartbeats.
- Hung/exited helpers recover with bounded exponential backoff.
- Failed processor delivery/flush/process operations fail closed into recovery
  rather than allowing silent controller/component state divergence.
- The realtime OBS filter uses bounded waiting and keeps dry audio when a valid
  wet result is unavailable in time.

Current scope / limitations
---------------------------
- Windows x64 runtime.
- Mono/stereo float32 audio effects.
- Complete restartComponent() I/O reconfiguration is still partial.
- Sidechain / multiple audio buses are not fully supported.
- VST3 instruments/MIDI are not supported.
- Arbitrary multichannel and float64 fallback are not yet supported.
- Linux/macOS runtime packages are not currently shipped.
- The Safe VST3 Rack is a later phase; v0.4.0 remains one effect per OBS filter.

Phase S stable means the Single Host state/recovery/DSP-isolation architecture
is now the stable release baseline. It is not a guarantee that every third-party
VST3 plug-in is compatible.

Security note
-------------
Process isolation is crash/hang containment, NOT a malware sandbox. Only load
plug-ins you trust.

CI / release validation
-----------------------
The Windows release pipeline validates:
- protocol v6 tests and state/recovery invariants;
- SPSC realtime queue tests;
- isolated host build;
- isolated scanner build and smoke execution;
- hang-watchdog and control-stall/DSP-survival fault tests;
- checkpoint restoration across helper death/recreation;
- real OBS module compilation against pinned OBS/libobs 32.2.2;
- portable ZIP layout;
- Smart Installer install/uninstall/reinstall using a remembered portable path;
- SHA-256 checksums for published assets.

Real-world third-party VST3 compatibility still benefits from compatibility
reports and plug-in-specific testing.
