Rack master signal path

The meters and faders describe the actual shipping Rack path.

The master console is not decorative UI. Input Trim, Output Fader and broadcast telemetry are attached to the generated shipping Rack helper while preserving the isolated-helper architecture.

IN

Input Trim before the chain

Input Trim defaults to 0.0 dB, is applied before the serial VST3 chain and uses bounded smoothed gain changes. The input L/R meters observe the post-trim signal.

OUT

Output Fader after the chain

Output Fader defaults to 0.0 dB and remains authoritative after the chain, including fail-dry output, so deliberate attenuation does not jump back to full level when a wet result is unavailable.

METER

Final-output loudness

Output L/R peaks, LUFS-I and dBTP observe the final post-output-fader audio delivered to OBS.

Metering contract

Broadcast metrics are bounded telemetry, not a claim of universal loudness compliance.

The implementation follows a deterministic broadcast-oriented measurement contract: integrated loudness uses K-weighting and gated ITU-R BS.1770 / EBU R128-style structure; true peak uses reconstructed inter-sample estimation. Final platform delivery targets and compliance remain the user's responsibility.

✓
LUFS-I structure. 400 ms windows with 75% overlap, -70 LUFS absolute gating and -10 LU relative gating.
✓
dBTP reconstruction. 4× quarter-sample reconstruction with a 33-tap windowed-sinc polyphase interpolator and session-max hold.
✓
Realtime boundary. Telemetry publication is atomic/lock-free and avoids UI calls, mutex waits and dynamic audio-path allocation.
✓
Reference coverage. Deterministic tests cover loudness gating and inter-sample true-peak behavior.

Persistence evidence

Recall testing covers the actual working Rack, not only reusable presets.

Real OBS validation changed settings in commercial split controller/processor VST3 effects across successive OBS sessions. The latest working Rack and full DSP state restored on restart, including cases where controller metadata alone would not have been sufficient.

✓
DSP-safe capture frontier. State capture is coordinated away from concurrent vendor processing.
✓
Dry-first restore. Slow chains can remain safely available as dry/pass-through while materializing.
✓
Split-component synchronization. Native GUI edits and preset-wide parameter resyncs reach processor state before capture.
✓
Explicit storage failure. The product does not present a writable Rack as normally persistent when durable session storage is unavailable.
