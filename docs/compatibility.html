Compatibility · v0.5.0 stable

Built for the VST3 effects people actually use in studio workflows.

The current stable host targets Windows VST3 audio effects and is designed for broad compatibility with conventional popular studio processors. It is not a vendor whitelist, and it does not claim every advanced VST3 topology is complete.

Real-machine qualification with popular studio plug-ins

The v0.5.0 line has been exercised on a real Windows/OBS machine with commercial effects including:

  • iZotope — Ozone 11, RX 9 Spectral De-noise
  • FabFilter — Pro-Q 3, Pro-C 2, Pro-R, Saturn
  • Waves — SSL Channel
  • Klevgrand — Brusfri
  • Neuro Audio — Westwood
  • Process Audio — Sugar
This is compatibility evidence, not a whitelist. A VST3 effect does not need to appear in this list to work. The scanner does not decide compatibility by vendor name.

Why this covers a large part of the studio-effect world

The stable scope is intentionally focused on the most common OBS use case: audio insert effects. EQ, dynamics, restoration, reverb, saturation, limiting and mastering-style processors usually fit that model far better than synths, samplers or unusual multi-bus instruments.

That focus lets the project target broad compatibility with the kinds of VST3 processors creators and engineers actually want for microphones, music, voice, streaming and final-bus processing, while keeping unsupported feature classes explicit.

Why instruments are hidden today

VST3 audio effects and instruments share the same broad VST3 audio-module class family. The scanner therefore looks at VST3 subcategory metadata. Plug-ins explicitly marked as Instrument without an Fx role are excluded from today's OBS insert-effect list, while normal Fx and hybrid Fx/Instrument classes remain eligible.

This prevents synths and samplers from confusing a user who only wants an audio filter, without using an aggressive effect whitelist that could hide legitimate vendor plug-ins with incomplete metadata.

Instruments and MIDI are a roadmap feature, not a rejected idea

Instrument hosting needs more than simply showing synths in the list. A dependable implementation needs MIDI input, VST3 event-bus delivery, event timestamps, note/controller state, monitoring and recovery behavior. Those are planned as part of the future live-performance direction.

See the public roadmap for rack, chain, routing, sidechain, MIDI and VST3 instrument plans.

How to report a plug-in that does not work

Please include enough detail to make the failure reproducible:

  • OBS Studio version
  • Windows version
  • VST3 product and exact version
  • whether the problem is discovery, loading, vendor GUI, DSP or state restore
  • the exact filter status message
  • relevant [obs-safe-vst3] OBS log lines

Open a public compatibility issue on GitHub.
