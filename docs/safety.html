Process isolation

Keep third-party VST3 code out of obs64.exe.

The Single filter and Rack use different external helpers, but share the same safety principle: vendor DSP/UI runs across a process boundary and OBS keeps a dry fallback path.

◈
Crash isolation, not a sandbox

The helper boundary is for common plug-in crashes/hangs and real-time failure containment. It does not make malicious native code safe.

Two helper shapes

1
Single filter
obs-safe-vst3-host.exe hosts one selected VST3 effect and its vendor editor.
8
VST3 Rack
obs-safe-vst3-rack-host.exe owns one Rack Editor and up to eight serial VST3 effects.
✓
OBS stays on its side
The OBS module exchanges audio/control data with the helper instead of deliberately loading vendor VST3 code into obs64.exe.
Failure behavior

Prefer dry audio to blocking OBS.

DSP

Dry fail-open

If a valid isolated wet result is not ready inside the real-time deadline, the OBS-side filter can keep the dry signal rather than wait indefinitely on vendor code.

IPC

Process boundary

A helper crash or hang is separated from the OBS process boundary. Recovery behavior depends on the filter and failure state, but OBS does not need to host the vendor module in-process.

OFF

Bounded Rack shutdown

v0.6.0 requests Rack shutdown immediately, wakes the IPC paths and uses a short bounded graceful wait before forcing a stuck Rack helper to exit. The deterministic hung-helper fixture finishes in about 0.30 s.

Rack-specific model

One process per Rack — not one per slot.

Every Rack slot shares the same external Rack helper. This keeps the v0.6.0 architecture compact, but it means a severe helper-level failure is a Rack-level process failure.

obs64.exe
   │ Rack IPC
   ▼
obs-safe-vst3-rack-host.exe
   ├─ Rack Editor
   ├─ Slot 1 VST3
   ├─ Slot 2 VST3
   └─ … Slot 8
Do not interpret “Rack isolation” as per-slot process isolation. Finer correlated slot failure quarantine/recovery is future hardening work.
Preset safety

Saved state should not destroy a working Rack.

✓
Load is a copy. Editing the working Rack after loading does not silently mutate the saved preset.
✓
Explicit Update. Saved preset content changes only through an intentional Update action.
✓
Corrupt-load protection. A failed/corrupt preset load must not replace the current working Rack.
✓
Missing placeholders. Unavailable plug-ins can remain represented as pass-through slots so topology/state is not silently erased.
Security boundary

A VST3 still runs as native code.

The helper runs with the permissions of the current Windows user. A malicious plug-in could access files, networking or other APIs available to that account.

Only install VST3 software from vendors you trust. Do not disable Defender or SmartScreen globally for this project.
Windows package signing

Current releases are not commercially Authenticode-signed.

Windows may show Unknown publisher or a SmartScreen reputation warning. Download from the official GitHub Releases page and verify SHA256SUMS.txt when you want to confirm file integrity.
