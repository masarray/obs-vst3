Why it exists

VST3 support without turning setup into a developer project.

Install it, pick a plug-in, open its normal interface, and keep streaming. The architecture is technical; the workflow should not be.

⛨

Crash-isolated hosting

Third-party VST3 code is loaded by a separate helper process. The isolation boundary is designed to protect OBS from plug-in process failures.

⌕

Automatic discovery

Choose from installed VST3 effects, rescan when needed, or browse to a custom VST3 location. No manual Class ID workflow for normal use.

▣

Real plug-in interfaces

When a VST3 provides a native editor, open the plug-in's own GUI. When it does not, simple generic parameter controls can be shown instead.

Getting started

Three steps from download to your first VST3.

The recommended path is the Windows Smart Installer. Portable/manual installation remains available for advanced or portable OBS setups.

Close OBS and install

Run the Setup x64 file. The installer asks you to confirm the exact OBS Studio folder you actually launch and refuses to copy over a running OBS instance.

Add the audio filter

Open OBS, select your microphone or audio source, choose Filters → + → VST 3.x Plug-in.

Pick your effect

Choose an installed VST3, rescan, or browse to a custom bundle. Click Open Plug-in Interface when the effect has a GUI.

Verify. Don't disable security.

The project publishes source code and SHA-256 checksums. It will never ask you to turn off Microsoft Defender or antivirus just to install it.

FAQ

Questions users should not need to ask the developer twice.

Will this replace OBS's VST2 support?

No. OBS already has a VST2 filter. This project exists for VST3 audio effects and keeps that scope clear.

Does “isolated” mean I can safely load any random VST3?

No. Crash isolation is not a malware/security sandbox. Only load VST3 plug-ins you trust. The separate helper process is designed to contain plug-in process crashes/hangs from the OBS process, not to make malicious software safe.

I still see “Enabled”, “VST3 Class ID”, or “Live deadline fraction”. What happened?

OBS is loading an older development copy. Run the current Preview 2 Setup again and confirm the exact OBS Studio folder you actually launch. Preview 2 also cleans up known legacy project-owned copies that can shadow the new module. An old filter instance name on the left may remain because OBS stores scene names; the right-side properties are the important check.

My plug-in is not listed.

Use Rescan Installed Plug-ins. Confirm it is a 64-bit VST3 audio effect. For non-standard locations, use Browse / Custom VST3.

My VST3 has no graphical editor.

Some plug-ins do not provide a native UI. The host can expose generic Plug-in Controls when available instead.

What happens if a plug-in crashes while OBS is live?

The VST3 runs in the isolated helper, not inside OBS. The bridge is designed to fail open to dry audio on helper/process failure or missed processing deadlines rather than deadlock the OBS audio callback. Automatic restart/recovery policy is still evolving, so reloading the filter or restarting OBS may be required after a failed third-party plug-in.

Is Preview 2 “stable”?

It is intentionally labeled Public Preview. Automated runtime and installer acceptance are strong, but universal VST3 compatibility requires broad real-world testing across many vendors, editors, licensing systems, and long sessions.

Try your VST3 in OBS—without putting it inside OBS.

Start with the Smart Installer. If a plug-in behaves differently than expected, report the exact plug-in/version so the compatibility picture becomes more useful for everyone.
