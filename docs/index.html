Rack workflow

v0.6.0 adds the polished Rack Editor, floating native plug-in windows and a first-class preset workflow.

Open Rack

Add VST3 Rack in OBS and use Open Rack. The editor belongs to the external Rack helper and can be closed while DSP continues.

Build the chain

Search the catalog, Add Effect, drag/reorder slots, bypass or replace them, then use Open UI for each vendor editor.

Save the sound

Save As creates a named preset. Loading is a copy; normal edits do not silently mutate the saved preset. Update is always explicit.

◈
Outside obs64.exe

Single uses one isolated helper per effect. Rack uses one isolated helper per Rack, containing the Rack Editor and its serial VST3 slots.

Safety architecture

Designed to fail dry.

Third-party native code is moved across a process boundary so a common plug-in crash or hang does not need to live inside OBS itself.

✓
Dry fail-open
When a valid isolated wet block is unavailable in time, OBS keeps a dry path.
✓
Bounded Rack shutdown
A stuck Rack helper gets only a short graceful-exit budget before forced termination, avoiding the old multi-second close delay.
✓
Scanner isolation
Discovery is kept away from the OBS process.
Crash isolation is not a malware sandbox. A VST3 is native code with the current Windows user's permissions. Only use plug-ins you trust.

FAQ

Common questions

Does OBS itself now support VST3?

This project adds its own OBS filters and VST3 host processes. It does not change OBS's built-in VST filter.

Does each Rack slot get its own process?

No. v0.6.0 uses one isolated helper process per Rack, with up to eight serial slots inside it.

Can I use my plug-in's native GUI?

Yes, when the VST3 exposes a supported native editor. In Rack, use Open UI on the slot.

Are Rack presets live-linked?

No. Loading a preset creates an independent working Rack. Only explicit Update changes the saved preset.

Does it support instruments, MIDI or parallel routing?

Not in v0.6.0. The Rack is intentionally a serial mono/stereo Float32 audio-effects lane.
