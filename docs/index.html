The missing layer

The plug-in world moved forward. OBS's built-in VST filter did not move to VST3 yet.

OBS's official VST filter documentation currently lists VST3.x as unsupported and warns that some VST plug-ins can crash OBS. Meanwhile, many modern studio processors are distributed primarily—or only—as VST3.

Reliability before features

Live software should fail gracefully.

OBS's own VST documentation warns that some VST plug-ins may crash and recommends saving or backing up settings when experimenting. This project is designed around a different failure boundary.

✓
VST3 runtime outside OBS. The third-party module and vendor GUI live in obs-safe-vst3-host.exe, not obs64.exe.
✓
Scanner isolation. Discovery probes plug-ins outside OBS instead of deliberately loading every candidate into the broadcast process.
✓
Dry fail-open audio. If a valid wet result is not available in time, the filter is designed to keep the original dry audio rather than intentionally block the realtime path.
✓
State-aware recovery. Helper failures use watchdog detection, bounded backoff and state restoration so a bad plug-in load is less likely to destroy the user's live workflow.
Crash isolation is not a malware sandbox and cannot guarantee that every driver, OS or hardware failure will never crash OBS. It is a concrete architectural boundary for third-party VST3 failures. Read the exact safety model →

FAQ

What creators want to know before installing VST3 in OBS

Does OBS Studio already support VST3?

OBS's official built-in VST filter documentation currently lists VST3.x as unsupported. OBS Safe VST3 Host exists specifically to fill that gap for Windows VST3 audio effects.

Can I use professional mastering plug-ins in OBS?

Yes, when the VST3 audio effect fits the current host scope. Real-machine qualification has included popular processors from iZotope, FabFilter, Waves and other studio vendors. The final sound still depends on your source, plug-in and settings.

Will a bad VST3 crash OBS?

No native host can honestly guarantee zero crashes from every driver, OS, hardware or malicious-code failure. This project reduces the plug-in-specific risk by keeping third-party VST3 DSP and GUI code outside obs64.exe, isolating scanner probes, using bounded recovery and keeping dry audio when wet processing is unavailable.

Does it support every VST3?

The current stable product targets VST3 audio effects, not instruments/MIDI or every possible advanced bus topology. It is designed for broad compatibility with conventional popular studio effects and is not based on a vendor whitelist.

Will it support VST3 instruments, MIDI, chains and sidechain?

Yes, those are explicit roadmap directions: Safe VST3 Rack, chains, routing/sidechain, MIDI event support and VST3 instruments for live-performance workflows.
