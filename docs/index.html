v0.6.1 Rack surface

Compact like an audio device, not a utility dashboard.

The current Rack surface is deliberately quiet: less repeated text, more room for the plug-in chain, and a focused master console for the controls that matter during live operation.

LEAN

Minimal-noise slots

Compact one-row strips use the health LED for enable/bypass, the plug-in name for opening the vendor UI, and one small action affordance for topology operations.

0dB

Real master gain

Input Trim is applied before the VST chain and Output Fader after it. Both default to transparent 0.0 dB and use bounded smoothed gain changes.

LUFS

Final-output loudness

LUFS-I and reconstructed dBTP observe post-output-fader audio—the actual level path delivered to OBS rather than a disconnected UI estimate.

Stable topology UX

Chain edits stay visually calm while authoritative state changes.

The Rack keeps the last committed topology visible until the next authoritative snapshot arrives. Controls become temporarily interaction-disabled without flashing the entire surface, and the reserved scrollbar gutter prevents row-width jumps as chains grow.

LED

Direct slot interaction

Click the status LED to enable/bypass and the plug-in name to open the vendor editor.

+

One topology menu

Replace, insert, move and remove live behind one compact slot action instead of repeated controls on every row.

CALM

Flicker-resistant changes

Pending topology changes preserve the committed Rack picture until the new state is ready, reducing visual noise during live editing.

v0.6.1 stable recall

Your working Rack survives normal OBS restarts automatically.

Named presets are still available for reusable chains, but normal session continuity no longer depends on remembering to create one.

SAVE

Durable working state

Each OBS Rack owns a CRC-protected, atomic working-session snapshot with last-known-good recovery for topology, bypass and VST3 state.

DRY

Dry-first restore

Slow third-party chains restore behind a usable dry path and publish only when the complete restored generation is coherent.

DSP

State matches the sound

Split controller/processor VST3 editor changes are synchronized into processor state before capture, improving full DSP recall after restart.

🛡
Built around failure boundaries

VST3 runtime, vendor UI and scanning are separated from the OBS process by architecture.

Reliability before feature count

The broadcast process should not own third-party VST3 code.

✓
Separate helpers. Single Host and Rack each use isolated helper-process boundaries.
✓
Isolated scanning. Candidate probing is kept outside OBS.
✓
Bounded realtime behavior. An unavailable wet result falls back to original dry/pass-through audio.
✓
Authoritative output fader. User attenuation remains applied even on fail-dry output.
✓
DSP-safe state capture. Rack persistence does not require the realtime path to wait on a control mutex.
Crash isolation is not a malware sandbox and is not a promise that Windows, OBS, drivers or hardware can never fail. Only install VST3 plug-ins from vendors you trust. Read the exact boundary →
Release confidence

Public binaries come from a repeatable release pipeline.

The v0.6.1 runtime candidate passed focused Rack regressions, master/metering visual and numerical contracts, main CI and Compatibility Test Build on one exact source head. Real OBS testing then confirmed the latest working Rack and full VST3 DSP state across repeated restarts. The public release pipeline rebuilds against pinned OBS/libobs, validates packaging and the Smart Installer, and publishes SHA-256 checksums beside the binaries.
