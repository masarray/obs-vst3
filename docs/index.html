Why this exists

Modern plug-ins belong in your audio workflow—not in your troubleshooting routine.

OBS creators should be able to shape a microphone or program feed with familiar VST3 tools without first learning a hosting architecture. OBS Safe VST3 Host keeps the everyday workflow straightforward and pushes isolation, recovery and state handling into the background.

Safety without the scary wording

If a third-party plug-in misbehaves, OBS should not be the first thing it owns.

The project places VST3 runtime work, vendor interfaces and scanning behind separate process boundaries. That does not turn unknown plug-ins into safe software, but it gives live production a better failure boundary than loading everything directly into the OBS process.

✓

Separate helper processes. Third-party VST3 work is kept outside obs64.exe.

✓

Dry-first behavior. When wet audio is unavailable, the design prefers the original signal over silence.

✓

Output attenuation remains authoritative. Your output fader still matters on fail-dry output.

✓

No false promise. Isolation is not a malware sandbox; only install VST3s from vendors you trust.

Straight answers

Before you install.

Does this package include VST3 effects?

No. It is a VST3 host for OBS. You install the audio plug-ins you want from their own vendors, then select them inside the Single Host or Rack.

Will every VST3 plug-in work?

No host can promise universal compatibility with every third-party plug-in. The project has a documented compatibility boundary and test process. Check the compatibility page for the current support model.

Does the Rack remember my chain after restarting OBS?

Yes. The current stable Rack includes durable working-state recall for normal restart continuity, while named presets remain available for reusable setups.

What happens if the processed path is not ready?

The runtime is designed to keep a bounded dry/pass-through path available instead of making the realtime audio thread wait indefinitely for wet processing.

Is macOS supported?

The current public stable package is Windows x64. The website and release assets should be treated as Windows-only unless a future release explicitly says otherwise.
