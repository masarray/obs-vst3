Product roadmap

From safe VST3 effects to a complete live audio platform for OBS.

The stable v0.5.0 line solves today's VST3 audio-effect gap. The roadmap grows that foundation into effect racks, routing, sidechain, MIDI and VST3 instruments for live performance.

Roadmap, not a release-date promise. Major features should ship only after their realtime, lifecycle, recovery and compatibility behavior is strong enough for a live broadcast.

Stage 1 — Safe VST3 Effects — available now

The current stable product keeps the workflow deliberately simple: one VST3 audio effect per OBS filter, with installed discovery, native vendor GUI, isolated runtime/scanning, state persistence, recovery and dry fail-open behavior.

  • Native OBS VST 3.x Plug-in filter.
  • Automatic discovery and manual `.vst3` browsing.
  • Real vendor editor and foreground workflow.
  • Crash-isolated VST3 runtime and scanner.
  • State restore, watchdog health monitoring and bounded recovery.

Stage 2 — Safe VST3 Rack

The next major platform step is a rack that turns multiple single effects into one live processing chain.

Input → Noise Reduction → EQ → Compressor → Saturation → Limiter → OBS Output
  • Multiple VST3 effects in one rack.
  • Insert, remove, reorder and per-slot bypass.
  • Rack presets and deterministic state restore.
  • Aggregate latency handling.
  • Per-slot health/recovery behavior when one effect fails.
  • Fast access to each native vendor GUI.

Stage 3 — Routing and Sidechain

A rack becomes significantly more powerful when it can route signals instead of only running a straight serial chain.

  • Sidechain input paths.
  • VST3 multi-bus audio handling.
  • Explicit input/output routing.
  • Parallel processing where practical.
  • Richer multichannel negotiation and latency strategy.

Example workflows include music ducking from a microphone, parallel compression, restoration-before-effects branches and more advanced broadcast/mastering chains.

Stage 4 — MIDI and VST3 Instruments

Instrument hosting is intentionally a later phase because a serious implementation needs a real event/timing model—not simply letting synths appear in today's effect list.

  • VST3 instrument class support.
  • MIDI input device selection.
  • Timed note/controller event delivery.
  • Sustain, pitch and modulation handling.
  • Instrument state/preset persistence.
  • Low-latency live monitoring and recovery designed to avoid stuck-note behavior where possible.

The goal is to let a creator play a piano, synth or sampler from a MIDI controller directly into an OBS live-performance setup.

Stage 5 — Live Performance Rack

The long-term vision combines effects, instruments and routing into an OBS-native live rig:

  • instrument + effect racks;
  • MIDI-mapped controls and macros;
  • scene-aware rack presets and snapshots;
  • fast A/B chains and recall;
  • metering per processing stage;
  • performance-oriented switching without unbounded audio-path stalls.

The product vision

A creator should be able to build a studio-quality live audio rig inside OBS: use mastering-style processors for stream audio today, build routed racks and sidechains next, and eventually perform live with MIDI-controlled VST3 instruments—all without forcing a separate DAW into common live workflows.

What will not be compromised

Every stage must preserve the architecture that makes the current product valuable:

  • third-party plug-in code stays outside obs64.exe;
  • realtime processing stays bounded;
  • failure degrades gracefully rather than intentionally blocking OBS;
  • advanced features remain optional so simple users still get a simple filter;
  • compatibility claims stay evidence-based.
